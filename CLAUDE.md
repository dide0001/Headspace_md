# CLAUDE.md – fælles hukommelse for projektet

Læs denne fil først. Kør `git pull --rebase`, og læs derefter `status/diego.md`, `status/aviaja.md`, de nyeste filer i `beslutninger/` og **alt, hvad den anden person har pushet siden din sidste log** (`git log`, den andens logs og afsnittet "Nyt fra …" i din egen seneste log). Du skal kende den andens arbejde, før du går i gang – fx Aviajas prototyper, før Diegos Claude bygger WordPress, og Diegos sitemap og designsystem, før Aviajas Claude designer.

## Regler for Claude i dette repo
- Skriv kun i din egen persons filer (log/<navn>/, status/<navn>.md). Ret aldrig den andens filer.
- En ny beslutning = en ny fil i beslutninger/ (ÅÅÅÅ-MM-DD-emne.md). Ret ikke gamle beslutningsfiler.
- Ret kun CLAUDE.md, når begge har sagt ja til ændringen.
- Altid git pull --rebase før git push.
- Skriv på dansk. Brug kun tal og citater, der står i kilderne – spørg hellere end at gætte.

## Rapportens opbygning (vejleder Michaels krav)
- Bygget som Double Diamond: Fase 1 Discover (D1–D5), Fase 2 Define (D6–D10), Fase 3 Develop (D11–D20), Fase 4 Deliver (D21–D22). Konklusion besvarer problemformuleringen ud fra delkonklusionerne.
- Hvert hovedafsnit har en indledning (3–5 linjer: hvilke D'er + metoder/data) og en delkonklusion (svarer på hvert D i rækkefølge og leder videre).
- Delspørgsmål: Målgruppe D1–4, Kommunikationsstrategi D5–9, UX/IA D10–12, UI D13–16, Teknik D17–20, Evaluering D21–22.
- Brug ikke ordet "indholdssøjler" – skriv "strategisk ramme for indhold".
- SocialSpace og appen er droppet og nævnes kun i perspektiveringen.
- Kilder angives som (Afsender, årstal) og står i litteraturlisten.
